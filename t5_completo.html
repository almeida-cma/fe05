📝 Anatomia de um formulário HTML

💡 Conceito fundamental: o elemento <form> é o contêiner que agrupa os campos de entrada, botões de envio e atributos que dizem ao navegador para onde, como e com qual codificação enviar os dados. Sem ele, os campos são apenas decoração visual.

🔍 Cada atributo do <form> em detalhe

      

        
          
AtributoValores típicosFunção

        
        
          
actionURL do endpointPara onde os dados serão enviados quando o formulário for submetido. Se omitido, os dados vão para a própria página.

          
methodget ou postMétodo HTTP de envio. GET coloca os dados na URL e eles ficam visíveis; POST envia no corpo da requisição, invisível ao usuário — recomendado para senhas e dados sensíveis.

novalidatebooleanoDesliga a validação automática do navegador para o formulário. Pouco usado, mas existe.

          
enctypeapplication/x-www-form-urlencodedCodificação dos dados enviados. Formulários com upload de arquivos exigem multipart/form-data.

        
      


      
🆔 name vs id: o erro mais comum

      

        ⚠️ Atenção: name é o que identifica o campo no servidor, quando o formulário é enviado. id é o que identifica o elemento na página — usado por CSS, JavaScript e pela associação com <label for="...">. Um campo sem name simplesmente não é enviado. Um campo sem id fica fora da rotulagem acessível.
      


      

        
        
        
        
        
      


      

        ✅ Regra prática: todo input, select ou textarea precisa de name (para chegar ao servidor) e de id (para se associar a um <label>). Não são sinônimos e um não substitui o outro.
      

    

  


  
  

    

      
🎛️ Tipos de <input>: o type define o comportamento

      
O atributo type transforma o mesmo elemento <input> em campo de texto, senha, data, cor, e-mail, número, barra de intervalo, hora ou URL. Cada tipo traz validação nativa e teclado contextual no celular.

🎯 Regras invariáveis dos types checkbox e radio

      

        🚨 Regra de ouro: em um grupo de radio, todos os inputs do grupo precisam ter o mesmo name. Só assim o navegador trata como exclusivo — quando o usuário escolhe uma opção, as demais são desmarcadas automaticamente. Em checkbox, o mesmo name agrupa as opções para envio como array no servidor, mas o usuário pode escolher várias.
      


      

        
        

          
          
          
          
        


        
        

          
          
          
        


        
      

    

  


  
  

    

      
✅ Validação nativa da HTML5

      
O HTML5 introduziu atributos que dão ao navegador a responsabilidade de checar o valor de um campo antes da submissão. Nenhuma linha de JavaScript é necessária para os casos comuns.


      
🔧 Os atributos de validação mais usados

      

        
          
AtributoEfeitoExemplo de uso

        
        
          
requiredCampo obrigatório. Impede submissão se estiver vazio.<input type="email" required>

          
minlengthMínimo de caracteres.<input type="text" minlength="3">

          
maxlengthMáximo de caracteres.<input type="text" maxlength="20">

          
minValor mínimo para number, date, time, range.<input type="number" min="18">

          
maxValor máximo para number, date, time, range.<input type="number" max="99">

          
stepIncremento do number e do range.<input type="number" step="5">

          
patternExpressão regular para validar o texto.<input type="tel" pattern="[0-9]{11}">

          
placeholderDica visível quando o campo está vazio. Não afeta o valor.<input placeholder="Digite seu nome">

          
autofocusFoco automático ao carregar. Só um por página.<input autofocus>

          
autocompleteSugestões do navegador ligadas ou desligadas.<input autocomplete="off">

          
multipleAceita vários valores (email, file).<input type="email" multiple>

        ⚠️ Limitação importante: a validação nativa do HTML5 é conveniência de UX, não segurança. Ela pode ser desativada removendo o atributo do DOM com o DevTools, ou enviando a requisição HTTP diretamente. A validação definitiva de dados acontece no servidor — no backend, não no navegador.
      

    

  


  
  

    

      
🧩 Elementos complementares ao formulário

      
Além do <input>, um formulário completo usa estas tags: <label>, <select>, <textarea>, <button>, <fieldset> e <legend>. Todas fazem parte do vocabulário dos formulários HTML5.


      
🏷️ <label> — o rótulo acessível

      
Existem duas formas de associar um rótulo a um campo:

      

        
          
FormaCódigoQuando usar

        
        
          
Explícita (envelopando)<label>Nome <input type="text"></label>Quando o texto é curto e cabe na mesma linha do input.

          
Por atributo for<label for="nome">Nome</label><input id="nome">Quando o layout separa o rótulo do campo. Essa é a forma recomendada.

        
      

      

        ✅ Por que importa: com <label for="id">, o leitor de tela anuncia o campo como "Nome, caixa de edição" em vez de apenas "caixa de edição sem nome". Clicar no rótulo também foca o campo.

🧩 <fieldset> + <legend> — agrupamento acessível

      
Para grupos de campos relacionados (dados pessoais, endereço, gênero), envolva-os em <fieldset> e dê um título com <legend>. O leitor de tela anuncia o título do grupo ao entrar nele.

♿ Acessibilidade do formulário — a mesma lógica do Tema 04

      
Formulários são mais sensíveis à acessibilidade do que tabelas, porque cada campo é interativo e precisa de três informações: nome, papel e estado. Quando falta qualquer uma, o usuário de leitor de tela não consegue usar o formulário.


      
🌳 Árvore de acessibilidade — formulário bem rotulado

      

        
RootWebArea "Cadastro"

        
  form ""

        
    textbox "Nome" nome acessível

        
      StaticText "Nome"

        
    textbox "E-mail" nome acessível

        
    checkbox "Lembrar-me" nome acessível

        
    button "Enviar"

      


      
🌳 Árvore de acessibilidade — formulário sem rótulo

      

        
RootWebArea "Cadastro"

        
  form ""

        
    textbox "" sem nome

        
    textbox "" sem nome

        
    checkbox "" sem nome

        
    button "Enviar"

      


      

        🚨 O impacto real: no primeiro caso, o leitor de tela anuncia "Nome, caixa de edição" e o usuário sabe o que preencher. No segundo, anuncia apenas "caixa de edição" — o usuário cego não faz ideia de qual dado o campo espera. Sem nome, o formulário é inutilizável.
      


      
💻 Conferir no Chrome

      

        

          
1

          

            Inspecione o input
            
Abra o formulário no Chrome, pressione F12, vá em Elements, clique no elemento <input>.

          

        

        

          
2

          

            Abra a aba Accessibility
            
Se a aba não estiver visível, clique em >> no topo do DevTools para revelar as abas ocultas.

          

        

        

          
3

          

            Verifique o campo Name
            
No bloco Computed Properties, olhe o valor de Name. Se for o texto do <label>, o campo está acessível. Se estiver vazio, o input não tem rótulo associado.
