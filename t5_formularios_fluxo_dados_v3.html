🏷️ Anatomia mínima de um formulário

O elemento <form> é o contêiner. Dentro dele, cada campo precisa de um rótulo (<label>) e de uma caixa (<input>). A ligação entre os dois é feita pelo par for + id. O nome que o dado vai levar para o servidor é dado pelo name.

<form> <label for="nome">Seu nome:</label> <input type="text" id="nome" name="nome"> <button type="submit">Enviar</button> </form>
Código O que significa
<form> Agrupa os campos. Nada é enviado fora dele.
<label> Texto visível que diz o que preencher.
for="nome" Liga o rótulo ao campo que tem mesmo id.
<input> A caixa em si. Não tem fechamento.
type="text" Define o comportamento: texto livre.
id="nome" Identifica o campo na página.
name="nome" Identifica o dado no envio.
<button> Dispara o envio.
⚠️ Atenção na diferença: id e name não são sinônimos. O id identifica o elemento na página (para o <label> e para o CSS). O name identifica o dado que vai viajar quando o formulário for enviado. Um campo sem name simplesmente não é enviado.

🔬 Experimento guiado — como comparar

      

        Siga estes passos:
        
    
          
  1. Baixe os dois arquivos. Salve na mesma pasta.
    2. 
          
  2. Abra 01_get.html no Chrome. Digite Ana no nome, clique em Enviar.
    3. 
          
  3. Olhe a barra de endereços. Você verá algo como file:///.../01_get.html?nome=Ana. Os dados apareceram na URL.
    4. 
          
  4. Volte. Abra 02_post.html. Digite Ana, clique em Enviar.
    5. 
          
  5. A URL continua limpa, mas o navegador reclama de erro — porque não há servidor para receber o POST.
    6. 
        

        O que você deduz disso?
        
    
          
  • GET é suficiente para uma demonstração local: os dados aparecem, você vê o que foi enviado.
    • 
          
  • POST esconde os dados — mas exige um destino preparado para receber.
    • 
          
  • Nenhum dos dois "salva" nada. Salvar exige armazenamento — e é o próximo assunto.
    •

        ⚠️ Desfazendo um mito: "POST é mais seguro que GET porque esconde os dados" — errado. Tanto GET quanto POST trafegam em claro. Quem protege contra interceptação é o protocolo HTTPS na conexão. POST é preferível para senhas por outros motivos (não fica no histórico, não fica na URL visível), mas nunca por criptografia.
      

    

  


  

    

      
📦 JSON + localStorage — guardando o dado dentro do navegador


      

        Ideia central: o localStorage é um armário dentro do navegador. Ele guarda texto. Para guardar um objeto (nome + e-mail), você transforma em texto com JSON.stringify. Para recuperar, transforma de volta com JSON.parse.

        ✅ O que provou: o dado saiu do formulário, virou texto, ficou guardado no navegador. Recarregar a página não apagou. Isso é persistência — diferente de uma variável JavaScript comum, que se perde ao recarregar.
      


      
⚠️ Três avisos sobre localStorage

      

        
    
          
  • É por navegador e por site — outro computador não vê.
    • 
          
  • Não é seguro para senhas, cartões e dados sensíveis.
    • 
          
  • Limpar os dados do navegador apaga tudo. Não é backup.
